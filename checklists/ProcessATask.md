# Checklist: Quy trình làm một task
- [ ] Đảm bảo task chỉ ở một thư mục duy nhất:
  - [ ] Khi tạo task mới, đặt file trong `tasks/data/TODO/`.
  - [ ] Khi bắt đầu làm task, di chuyển file sang `tasks/data/IN_PROGRESS/`.
  - [ ] Khi hoàn thành task, di chuyển file sang `tasks/data/DONE/`.
  - [ ] Khi review task chưa đạt, di chuyển file về `tasks/data/REOPEN/`.
  - [ ] Kiểm tra để chắc chắn không có task nào tồn tại ở cả hai folder.
- [ ] Tạo branch Git riêng cho mỗi task:
  - [ ] Tạo branch theo format: `dev-<taskID>`.
  - [ ] Khi bắt đầu task, tạo branch từ `staging`: `git checkout -b dev-<taskID> staging`.
  - [ ] Chỉ merge khi task hoàn thành và working tree sạch.
- [ ] Tạo tài liệu cho thư mục và file:
  - [ ] Với folder, tạo file `README.md` mô tả mục đích và nội dung chính.
  - [ ] Với file, tạo file `README_<tênfile>.md` mô tả mục đích, cách dùng, tham số đầu vào/đầu ra.
- [ ] Thêm dữ liệu vào Doc-Site khi có tài liệu mới:
  - [ ] Tạo file JSON trong `projects/doc-site/data/docs/<category>/xxx.json`.
  - [ ] Thêm entry vào `projects/doc-site/data/docs-manifest.json`: `{ "file": "<category>/xxx.json", "title": "Display Title" }`.
- [ ] Lập kế hoạch và lưu lại lịch sử hoạt động:
  - [ ] Trước khi làm, tạo plan (todo list hoặc task file).
  - [ ] Sau khi làm, log vào `logs/history.jsonl` với action/description/timestamp.
  - [ ] Ưu tiên dùng `make history-add` để log.
- [ ] Tạo plan document cho mỗi task:
  - [ ] Trước khi bắt đầu task, chuẩn bị plan mô tả: objective, steps, expected output, success criteria.
  - [ ] Plan có thể là file `.md` trong workspace, hoặc nội dung trong task JSON (nếu hệ thống hỗ trợ).
- [ ] Đặt tên file chuẩn:
  - [ ] Tên file phải bắt đầu bằng chữ thường.
  - [ ] Các từ tiếp theo viết hoa chữ cái đầu.
  - [ ] Không chứa ký tự đặc biệt hoặc khoảng trắng (có thể dùng ký tự '_' khi cần).
  - [ ] Các từ nối liền nhau (camelCase).
